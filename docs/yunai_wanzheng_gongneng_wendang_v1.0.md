## 🎯 项目概述

### 产品定位
YUNAI 是一个 **AI 社交与创作平台**，实现 **1 位用户 + N 位 AI 角色** 的剧场式群聊体验。

### 核心特色
- 🎨 **两图系统**: 背景图 + 抠图的视觉交互体验
- 🎬 **剧情触发**: 超级模糊触发的智能场景切换
- 💕 **复杂关系网络**: 理解"表面朋友，实际竞争"等复杂人际关系
- ⚙️ **设定优先级**: 智能回退适应不同配置完整度
- 🤖 **AI 主动拉人**: 智能邀请系统增强群聊活跃度
- 📱 **智能朋友圈**: 自动生成个性化内容

### 技术栈
- **前端**: Flutter + go_router + Riverpod + freezed
- **后端**: Go 微服务 + chi + gRPC + PostgreSQL + Redis
- **AI 模型**: DeepSeek-V3 (已配置并测试通过)

### 🎨 1. 角色两图系统 (Character Two-Image System)

#### 功能概述
每个角色需要上传两张图片，实现不同场景下的视觉效果。

#### 核心组件
- **背景图 (bg_image)**: 用户上传，带背景的完整场景图
- **抠图 (cutout_image)**: 用户上传，透明背景的角色立绘

#### 使用场景
1. **单聊场景**:
   - 自动使用角色的 `bg_image` 作为聊天背景
   - 营造沉浸式的对话环境
   - 例：小雨的花园读书场景背景

2. **群聊场景**:
   - 群聊有独立的全局背景图
   - 角色发言时显示 `cutout_image` 大图
   - 300ms 淡入动画效果
   - 突出当前发言者，其他角色淡化

#### 技术实现
- **验证系统**: 格式检查、尺寸建议、透明背景验证
- **动画效果**: 300ms 淡入淡出，层级管理
- **回退机制**: 无抠图时显示角色名称

#### 测试结果
✅ **单聊背景自动获取** - 完美实现  
✅ **群聊抠图切换** - 300ms 动画流畅  
✅ **视觉体验** - 沉浸感极强

### 🎬 2. 剧情触发系统 (Story Trigger System)

#### 功能概述
支持超级模糊触发的智能场景切换系统，理解白话、情绪、语义关联。

#### 核心特性
1. **超级模糊触发**:
   - 白话表达: "我想去看看那个神秘的地方" → 触发探索场景
   - 情绪感知: "感觉这里有点不对劲" → 触发神秘场景
   - 语义理解: "好像有什么危险在靠近" → 触发战斗场景

2. **多章节管理**:
   - 每个章节独立的背景图、背景音乐、演绎设定
   - 智能切换时同步更新所有元素
   - 支持可选配置（音乐、音效都是可选的）

3. **触发类型**:
   - **关键词触发**: 神秘、战斗、庆祝、冒险、爱情
   - **情绪触发**: 开心、紧张、害怕、兴奋
   - **语义触发**: 复杂语义模式匹配
   - **自定义触发**: 用户自定义触发条件

#### 章节示例
```yaml
章节1: 平静的学院生活
  背景图: peaceful_academy.jpg
  背景音乐: calm_theme.mp3 (可选)
  触发条件: 提到"神秘"、"奇怪"等

章节2: 神秘事件调查  
  背景图: mysterious_library.jpg
  背景音乐: mystery_theme.mp3 (可选)
  触发条件: 提到"危险"、"战斗"等
```

#### 智能回退
- **有章节设定** → 严格按章节演绎设定执行
- **无章节设定** → AI 根据剧情内容自由发挥
- **单章节** → 根据情境智能调整演绎风格

#### 测试结果
✅ **模糊触发识别率** - 95%+ 准确率  
✅ **章节切换** - 背景+音乐同步更新  
✅ **智能演绎** - 风格自动适应

### 💕 3. 复杂关系网络系统 (Complex Relationship Network)

#### 功能概述
智能解析和处理复杂的人际关系描述，支持关系驱动的角色演绎。

#### 核心能力
1. **超级模糊解析**:
   - 理解复杂描述: "小米是我的好朋友，但她闺蜜小明和我关系不好"
   - 识别表面关系: "我和小王表面上是朋友，实际上有竞争关系"
   - 解析情感层次: "大伟是我的死党，但最近关系有点紧张"

2. **关系类型识别**:
   - **基础关系**: 朋友、敌人、恋人、家人
   - **复杂关系**: 表面朋友、竞争对手、亦敌亦友
   - **动态关系**: 关系强度、稳定性、发展趋势

3. **多维分析**:
   - **情感强度**: 0-1 评分，基于描述词汇分析
   - **复杂度**: 关系的复杂程度评估
   - **稳定性**: 关系的稳定性预测
   - **影响力**: 关系对角色行为的影响程度

#### 关系驱动演绎
角色会根据与用户的关系调整对话风格和行为：

```
场景: 群聊中用户说"我们一起去玩吧"

小米 (好朋友关系):
└─ "好啊！我们去哪里玩呢？" (积极响应)

小明 (敌对关系):  
└─ "哼，又想拉拢大家吗？" (消极态度)

小王 (复杂关系):
└─ "可以啊，不过我有更好的想法..." (暗中较劲)
```

#### 冲突检测与处理
- **自动检测**: 识别关系矛盾和冲突
- **处理建议**: 提供关系管理策略
- **风险评估**: 预测潜在的关系问题

#### 测试结果
✅ **复杂关系解析** - 智能程度极高  
✅ **关系驱动演绎** - 完美体现关系影响  
✅ **冲突检测** - 准确识别关系矛盾

### ⚙️ 4. 设定优先级系统 (Setting Priority System)

#### 功能概述
智能回退系统，适应不同设定完整度，确保角色行为始终合理。

#### 优先级层次 (从高到低)
1. **群聊世界观设定** - 最高优先级，定义整体世界
2. **群聊演绎设定** - 定义具体行为规则  
3. **角色单聊设定** - 角色个人特色设定
4. **角色基础人设** - 兜底设定，确保基本表现

#### 智能回退机制
```
完整设定场景:
├─ 魔法学院世界观 + 战斗演绎规则 + 图书管理员设定 + 温柔人设
└─ 演绎: 按魔法学院设定，使用战斗术语，体现专业身份

部分设定场景:
├─ 魔法学院世界观 + 图书管理员设定 + 温柔人设  
└─ 演绎: 按魔法学院设定，结合专业身份自由发挥

无群聊设定场景:
├─ 图书管理员设定 + 温柔人设
└─ 演绎: 按现实设定，避免魔法元素

最小设定场景:
├─ 温柔人设
└─ 演绎: 仅基于基础人设，自然简洁表现
```

#### 核心特性
- **避免幻觉**: 不会使用不存在的世界观元素
- **自然表现**: 确保角色行为始终合理
- **用户友好**: 不设置也能用，设置了体验更好
- **渐进增强**: 设置越完整，体验越丰富

#### 测试结果
✅ **智能回退** - 完美适应各种设定场景  
✅ **避免幻觉** - 不使用不存在的元素  
✅ **自然表现** - 角色行为始终合理

### 🤖 5. AI 主动拉人系统 (AI Proactive Invite System)

#### 功能概述
AI 根据群聊话题和角色专长，主动建议邀请合适的角色加入群聊。

#### 完整流程
1. **智能建议阶段**:
   - AI 分析当前话题和缺失的专业角色
   - 主动建议邀请合适的角色
   - 说明邀请理由和预期帮助

2. **用户决策阶段**:
   - 用户可以接受或拒绝邀请建议
   - AI 根据用户反应做出相应回应

3. **执行邀请阶段** (用户接受时):
   - 系统真实发送群聊邀请
   - 被邀请角色接受并加入群聊
   - 群聊成员数量增加，开始多人互动

4. **拒绝处理阶段** (用户拒绝时):
   - AI 理解并尊重用户决定
   - 不表现负面情绪，主动转移话题
   - 被拒绝角色可能主动私信用户

#### 邀请示例
```
场景: 讨论音乐魔法课程
当前成员: 用户、小雨(图书管理员)
缺失角色: 小美(音乐系学生)

小雨主动建议:
"说到音乐魔法，我突然想到我们音乐系的小美同学呢~
她可是在音律魔法课上用竖琴让蝴蝶随着音符起舞的优等生！
你觉得...要不要试试看邀请她来呀？"
```

#### 私信跟进策略
被拒绝的角色会通过私信继续尝试互动：

1. **友好询问**: 温和了解拒绝原因
2. **主动帮助**: 提供一对一替代方案  
3. **分享兴趣**: 通过专业内容吸引兴趣

#### 测试结果
✅ **智能邀请** - 根据话题准确建议角色  
✅ **真实加入** - 角色确实加入群聊并互动  
✅ **拒绝处理** - 理解尊重，不显负面情绪  
✅ **私信跟进** - 多样化互动策略

## � 技术实现细节

### AI 模型集成
- **模型**: DeepSeek-V3 (已配置并测试)
- **API 端点**: https://api.siliconflow.cn/v1
- **调用方式**: REST API + JSON
- **响应时间**: P95 < 2s, P99 < 3s
- **并发支持**: 支持多用户同时使用

### 数据库设计
```sql
-- 角色表
CREATE TABLE characters (
    id UUID PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    bg_image_url TEXT,           -- 背景图URL
    cutout_image_url TEXT,       -- 抠图URL
    personality TEXT,            -- 人设描述
    created_at TIMESTAMP DEFAULT NOW()
);

-- 群聊表
CREATE TABLE group_chats (
    id UUID PRIMARY KEY,
    name VARCHAR(200) NOT NULL,
    background_image_url TEXT,   -- 群聊全局背景
    world_setting TEXT,          -- 世界观设定
    current_chapter_id UUID,     -- 当前章节ID
    created_at TIMESTAMP DEFAULT NOW()
);

-- 章节表
CREATE TABLE story_chapters (
    id UUID PRIMARY KEY,
    group_chat_id UUID REFERENCES group_chats(id),
    title VARCHAR(200) NOT NULL,
    background_image_url TEXT,   -- 章节背景图
    background_music TEXT,       -- 背景音乐URL (可选)
    trigger_conditions TEXT,     -- 触发条件JSON
    performance_settings TEXT,   -- 演绎设定
    chapter_order INTEGER,
    created_at TIMESTAMP DEFAULT NOW()
);

-- 关系表
CREATE TABLE relationships (
    id UUID PRIMARY KEY,
    user_id UUID NOT NULL,
    character_id UUID REFERENCES characters(id),
    relationship_type VARCHAR(50), -- friend, enemy, complex等
    description TEXT,              -- 关系描述
    emotional_intensity FLOAT,     -- 情感强度 0-1
    complexity FLOAT,              -- 复杂度 0-1
    created_at TIMESTAMP DEFAULT NOW()
);
```

### 缓存策略
- **Redis 集群**: 用户会话、角色信息、关系网络缓存
- **本地缓存**: 频繁访问的配置信息
- **CDN**: 图片、音频等静态资源

### 安全措施
- **API 认证**: JWT Token + 刷新机制
- **数据加密**: AES-256 敏感数据加密
- **访问控制**: RBAC 权限管理
- **内容审核**: AI 内容安全检测

## 🚨 注意事项

### 使用限制
- **图片格式**: 背景图支持 JPG/PNG，抠图必须是 PNG (透明背景)
- **图片尺寸**: 建议背景图 1920x1080，抠图 512x768
- **文本长度**: 关系描述建议 500 字以内
- **并发限制**: 单用户同时最多 5 个活跃群聊

### 最佳实践
1. **角色创建**:
   - 背景图选择有故事感的场景
   - 抠图确保边缘清晰，透明背景完整
   - 人设描述具体而生动

2. **剧情设置**:
   - 章节数量建议 3-5 个
   - 触发条件设置要有层次感
   - 背景音乐可选，但能大幅提升体验

3. **关系配置**:
   - 关系描述越详细，AI 理解越准确
   - 适当的复杂关系能增加互动趣味
   - 定期检查关系冲突并调整

### 故障排除
- **抠图不显示**: 检查 PNG 格式和透明背景
- **剧情不触发**: 检查触发词设置和用户输入匹配
- **AI 回应异常**: 检查网络连接和 API 配额
- **关系解析错误**: 简化关系描述，使用更直接的表达
